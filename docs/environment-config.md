# BrilDesk Environment Configuration Guide

## Overview

BrilDesk uses environment variables across two applications (`apps/web` and `apps/api`) and the Supabase configuration. The API stores secrets via Cloudflare Wrangler secrets; the web app uses Cloudflare Pages environment variables.

## Web App (`apps/web`)

These variables are set in the Cloudflare Pages dashboard (or in `.env.local` for local development).

| Variable | Required | Default | Description |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | — | Supabase project URL. Exposed to the browser (public). Example: `https://abc123.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | — | Supabase anonymous/public key. Used for client-side queries governed by RLS. Exposed to the browser. |
| `NEXT_PUBLIC_API_URL` | Yes | `http://localhost:8787` | Base URL of the Hono API worker. Example: `https://api.brildesk.com` |

**Notes:**
- All `NEXT_PUBLIC_` variables are embedded at build time and exposed to the client browser. They must not contain secrets.
- The Supabase anon key is safe to expose — it only grants access allowed by Row Level Security policies.
- For local development, the web app reads from `.env.local` (not committed to git).

## API (`apps/api`)

These variables are stored as Cloudflare Wrangler secrets (or in `.dev.vars` for local development).

### Supabase

| Variable | Required | Default | Description |
|---|---|---|---|
| `SUPABASE_URL` | Yes | — | Supabase project URL. Example: `https://abc123.supabase.co` |
| `SUPABASE_ANON_KEY` | Yes | — | Supabase anonymous key. Used to create per-request clients that forward user JWTs for RLS-governed access. |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | — | Supabase service role key. **Bypasses all RLS.** Used for webhook processing, admin operations, and beta signup handling. Keep this secret — never expose to clients. |

### WhatsApp Cloud API

| Variable | Required | Default | Description |
|---|---|---|---|
| `WHATSAPP_VERIFY_TOKEN` | Yes | — | Shared secret for Meta webhook hub verification (`GET /api/webhooks/whatsapp`). Also used as the HMAC secret for verifying inbound webhook signatures. Set this to any random string and configure the same value in Meta Developer Console. |
| `WHATSAPP_ACCESS_TOKEN` | Yes | — | Bearer token for the WhatsApp Cloud API. Used to send outbound messages via `POST graph.facebook.com/v21.0/{phone_id}/messages`. Obtain from Meta Developer Console -> WhatsApp -> API Setup. |
| `WHATSAPP_PHONE_NUMBER_ID` | Yes | — | The phone number ID from Meta's WhatsApp Business Platform. This identifies which phone number sends outbound messages. Find it in Meta Developer Console -> WhatsApp -> API Setup. |

### Email (Resend)

| Variable | Required | Default | Description |
|---|---|---|---|
| `RESEND_API_KEY` | Yes | — | API key from Resend (https://resend.com). Used to send transactional and marketing emails. |
| `RESEND_WEBHOOK_SECRET` | No | — | Shared secret for authenticating Resend delivery webhooks. If set, the webhook endpoint requires `?token=<secret>` query parameter. Recommended for production. |
| `EMAIL_FROM_ADDRESS` | No | `hello@brildesk.com` | Sender email address for all outgoing emails. Must be verified in Resend. |
| `API_BASE_URL` | No | `https://api.brildesk.com` | Public base URL of the API. Used to construct unsubscribe links in marketing emails. |

## Supabase Configuration

These are configured in `supabase/config.toml` for local development or in the Supabase dashboard for production.

| Variable | Where Configured | Description |
|---|---|---|
| `AUTH_GOOGLE_ID` | Supabase Auth settings | Google OAuth client ID. Enables "Sign in with Google". |
| `AUTH_GOOGLE_SECRET` | Supabase Auth settings | Google OAuth client secret. |
| `SUPABASE_JWT_SECRET` | Supabase project settings | JWT secret used to verify authentication tokens. Auto-generated by Supabase. |

## Local Development

### `.env.local` (Web App)

Create `apps/web/.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=http://localhost:54321
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key-from-supabase-start>
NEXT_PUBLIC_API_URL=http://localhost:8787
```

### `.dev.vars` (API)

Create `apps/api/.dev.vars`:

```bash
SUPABASE_URL=http://localhost:54321
SUPABASE_ANON_KEY=<anon-key-from-supabase-start>
SUPABASE_SERVICE_ROLE_KEY=<service-role-key-from-supabase-start>
WHATSAPP_VERIFY_TOKEN=my-local-verify-token
WHATSAPP_ACCESS_TOKEN=<your-whatsapp-access-token>
WHATSAPP_PHONE_NUMBER_ID=<your-phone-number-id>
RESEND_API_KEY=<your-resend-api-key>
```

The anon key and service role key are output by `supabase start`. For local development, WhatsApp and Resend variables can use test/sandbox credentials.

### Root `.env.example`

The root `.env.example` contains a template with all variables and their descriptions. Copy it to `.env` and fill in values:

```bash
cp .env.example .env
```

## Setting Secrets in Production

### Cloudflare Workers (API)

```bash
cd apps/api

# Set each secret interactively
wrangler secret put SUPABASE_URL --env production
wrangler secret put SUPABASE_ANON_KEY --env production
wrangler secret put SUPABASE_SERVICE_ROLE_KEY --env production
wrangler secret put WHATSAPP_VERIFY_TOKEN --env production
wrangler secret put WHATSAPP_ACCESS_TOKEN --env production
wrangler secret put WHATSAPP_PHONE_NUMBER_ID --env production
wrangler secret put RESEND_API_KEY --env production
wrangler secret put RESEND_WEBHOOK_SECRET --env production
```

### Cloudflare Pages (Web)

Set environment variables in Cloudflare Dashboard:
1. Go to Workers & Pages -> `brildesk-web-production` -> Settings -> Environment Variables
2. Add `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_API_URL`
3. Set for both Production and Preview environments

### Supabase (Auth)

Configure OAuth providers in Supabase Dashboard:
1. Go to Authentication -> Providers -> Google
2. Set Client ID and Client Secret
3. Add authorized redirect URL: `https://app.brildesk.com/api/auth/callback`

## Security Notes

- **Never commit secrets** to version control. `.env`, `.env.local`, and `.dev.vars` are in `.gitignore`.
- The `SUPABASE_SERVICE_ROLE_KEY` bypasses all Row Level Security. It must only be used server-side (in the API worker) for operations that require elevated access (webhooks, admin).
- `NEXT_PUBLIC_*` variables are embedded in the client bundle and visible to anyone. Only put non-secret values here.
- `WHATSAPP_ACCESS_TOKEN` may be a short-lived token (60 days) or a permanent system user token. Monitor expiration and rotate accordingly.
- `RESEND_WEBHOOK_SECRET` should be a cryptographically random string. Use `openssl rand -hex 32` to generate one.

## CORS Configuration

The API's CORS middleware (in `apps/api/src/index.ts`) allows these origins:
- `http://localhost:3000` (local development)
- `https://app.brildesk.com` (production)

If deploying to a different domain, update the CORS origin list in the API source code.
